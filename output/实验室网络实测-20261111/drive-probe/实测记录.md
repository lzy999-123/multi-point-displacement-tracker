# OV3660 输出驱动与 PCLK 门控对照

2026-11-11。用户确认无实验室路由器管理权限后，继续进行不依赖路由器修改的固件端对照。保持实验室 DH4504、QVGA 320×240、硬件 JPEG、20 MHz XCLK 和现有单播 VID1 路径。

使用隔离的正式固件副本，通过串口临时比较 OV3660 0x302c[7:6] 的输出驱动强度、0x4740[3:2] 的空闲 PCLK 门控，以及 ESP32 GPIO0 时钟输出驱动强度。位定义来自[乐鑫官方 OV3660 寄存器头](https://github.com/espressif/esp32-camera/blob/master/sensors/private_include/ov3660_regs.h)，读取到的 Git blob 为 `b5cf30a5b1da226aabbb368c5bed54fec33dc59b`，源码归档在项目 `tmp/lab-network-20261111/ov3660-source/`。

| 对照 | 寄存器实际读回（drive / clock） | 完整解码帧 / 15 秒 | 预热后逐秒最低 | 最大间隔 | 验收 |
| --- | --- | ---: | ---: | ---: | --- |
| 4x，GPIO drive 2，PCLK 无门控 | 0xc3 / 0x21 | 0 | 0 | 13000ms | 失败 |
| 1x，GPIO drive 0，PCLK 无门控 | 0x03 / 0x21 | 1 | 0 | 10537.42ms | 失败 |
| 1x，GPIO drive 0，PCLK 在空闲期门控 | 0x03 / 0x2d | 0 | 0 | 13000ms | 失败 |

三个设置命令的传感器写入与 GPIO API 均返回 0；读回支持设置确已生效。串口仍有 errno=12。RSSI 约 −50～−55 dBm。单张解码图像不是持续传图成功的证据，没有降低验收要求。测试按上述顺序在同一启动会话中进行，不能据此独立量化每个参数的因果影响，也没有测量电磁干扰或实际供电电压。

所有设置仅存在于本地诊断构建，未合入正式源文件。测试脚本在 finally 中恢复 `D:\esp32\build-out\lab-final-sta-20261111\bin\displacement_cam.ino.bin`。恢复是否完成以 `restore-sta-flash.log` 的摘要校验与脚本终态为准。

`build-info.json` 记录诊断应用和暂存源码哈希，`serial.log` 记录设置读回与发送错误，各子目录保存逐帧和逐秒接收证据。`summary.json` 的三个 passed 均为 false。本轮没有证明稳定视频已实现，也未进行位置/供电实物对照。
