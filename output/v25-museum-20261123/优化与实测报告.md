# 三视角藏品异动监测优化与实测报告（2026-11-23）

## 1. 需求定位与纯无线路径核对

用户明确系统定位：**不需要下位机/云台**；3 台固定机位 ESP32-CAM 从 3 个角度拍摄同一目标，画面**仅通过 ESP32 Wi-Fi 无线传输**到 Qt 上位机，锁定目标后持续输出变大、变小、移动、倾斜与消失提示（类博物馆藏品监控）。

代码核对结论：
- `host/` 中无 `cv::VideoCapture`、`QCamera`、UVC 或串口图像解码代码。
- `MainWindow::openChannel()` 经 `withVideoProfile()` 强制使用 `udp://<ip>:5006`（VID1 协议），`UdpFrameReceiver` 校验 `VID1` 魔数（`0x31444956`）、`device_id`（1～3）与对端 IPv4。
- USB CH340 串口仅用于供电、烧录与 115200 文本诊断日志；固件 `displacement_cam.ino` 仅提供 Wi-Fi UDP 5006（及兼容 HTTP 81）图传。

## 3. 主要优化内容

### 3.1 无线图传优化（固件 `v25` + 上位机收包诊断）
1. **平滑节拍底限 + AIMD 拥塞退让**（`esp32cam/displacement_cam/udp_video_profile.h`、`udp_send_policy.h`）：
   - 保留协议 `fps=0` 兼容性，新增 `adaptiveFloorMs()`（VGA 76 ms / QVGA 40 ms / SVGA 105 ms）作为三机共享 2.4 GHz 热点时的平滑发包基线。
   - 即使分片重试最终成功（`retried == true`），也在 `UdpSendPolicy::finish()` 中增加 `+8 ms` 自适应帧间隔（失败 `+24 ms`，上限 `+180 ms`），连续清洁帧后快速衰减回落。
2. **`chunk=0` 35 ms 零污染早退**（`displacement_cam.ino`）：首片在 35 ms 内无法入队时立即放弃旧帧，不再把残缺前半帧发入空口。
3. **PSRAM 补片缓存由 4 槽扩至 8 槽**（`kCacheSlots = 8`），与反馈窗口上限对齐；三机初始发包相位错开 `DEVICE_ID * 12 ms`。
4. **上位机分层收包诊断**（`host/udpstream.cpp`）：每 5 秒输出 `packets / complete / overwritten / stale / expired / assembly_max_ms`，清晰定位热点突发合包导致的单槽覆盖。

### 3.2 固定机位目标锁定与异动监测升级
1. **鼠标拖拽框选目标 ROI**（`host/videowidget.h/.cpp`、`channel.h/.cpp`、`autocontourdetector.h/.cpp`）：
   - 左键拖拽 ≥12 px 画出青色选框并锁定目标（完整支持 180° 画面旋转），单击仍兼容原有轮廓点选。
   - ROI 模式采用 **9 尺度模板匹配（0.62×～1.46×）+ 3D Lab 颜色直方图校验 + 局部外环背景 Lab 对比前景轮廓细化 + 原地大幅倾倒分割兜底**，可稳定监测静止、大幅移动（>120 px）、变大、变小、倾斜、消失与放回恢复；无目标且不看掩膜时跳过全帧 Canny，空闲处理耗时由 `1.5~2.7 ms` 降至 `0.0 ms`。
2. **位移方向提示**（`host/artifactmonitor.h`）：新增 `deltaX / deltaY`，变化说明直接标注“左移/右移/上移/下移 xx px”及面积比。

### 3.3 三视角博物馆融合看板与输出提示
- `MainWindow::updateFusionDecision()` 保留全部原有 `monitorState` 状态属性以兼容历史回归，同时新增 `monitorSeverity` 区分：
  - **单视角预警（1/3 路）**：提示单机位疑似遮挡或单视角变化；
  - **多视角联合确认（≥2/3 路）**：红警确认目标移走或变化，并自动综合解读“某视角缩放 + 侧视角位移 = 目标空间移动”。
- 新增：**异动声音提示开关**、**多视角确认告警自动截图存证**（保存至配置目录 `alerts/`）、**一键导出事件日志**。

## 6. 640×480 提升至 15 fps 专题调优与实测（2026-11-23 晚）

针对用户提出的将 640×480 提升至 15 fps 的需求，完成三组对比调优（保持 OV3660 27.7 fps 原生采集与 0 断流底线）：

1. **核心改动**：
   - `esp32cam/displacement_cam/udp_video_profile.h`：将 `Vga12` 质量区间调优为 `34 ~ 62`（目标字节 `5600`，合法范围上限 `<= 62`，处于 OV3660 硬件 `4..63` 寄存器范围内），`adaptiveFloorMs(Vga12)` 由 `76 ms` 提速至 `60 ms`（约 `16.4 fps` 推流基线）。
   - `esp32cam/displacement_cam/udp_send_policy.h`：当平均 JPEG 字节超过目标值 `1.5×` 时，质量步进提速为每 2 帧 `+2`，消除冷启动前 8 秒的大包冲击。
   - `host/mainwindow.cpp`：在 `onDeviceFound()` 增加 `127.0.0.x` 回环测试流保护，防止本地单元测试受局域网在线实机广播干扰。

2. **三轮实机实测数据对比（Redmi K70E 2.4 GHz 单射频热点，三路同时推流）**：

| 试验批次 | 参数 | 640×480 顺畅阶段平均显示 fps（ID1/2/3） | 640×480 最长间隔 / 零帧秒 / 重连 | 备注 |
| --- | --- | --- | --- | --- |
| `live-v25-vga15` | `floor=58 ms, q=26~54` | **14.60 / 15.30 / 14.85**（Phase 3） | 376~387 ms / **0 / 0** | 冷启动 `q=26` 爬坡慢，高纹理单帧达 9~10 KB（7~8 分片） |
| `live-v25-vga15-q60` | `floor=56 ms, q=34~60` + 快速爬坡 | **16.15 / 16.30 / 16.15**（Phase 1） | 308~377 ms / **0 / 0** | 320×240 同批达 **24.15 / 24.40 / 24.10 fps**；56 ms 跑满 352 包/秒，Phase 3 遇一次信道突发跌至 13.2~13.7 fps |
| **`live-v25-vga15-final`（最终定版）** | **`floor=60 ms, q=34~62` + 快速爬坡** | 顺畅瞬时 **16.2 / 13.8 / 16.6 fps**；热点休眠/信道扰动均值 **10.90 / 12.65 / 10.90** | 557~935 ms / **0 / 0** | 三档切换全通（320×240 **17.6/19.0/17.3**，800×600 **8.55/8.70/8.90**），全程 **0 零帧秒、0 重连** |

3. **物理边界结论**：
   - OV3660 硬件 JPEG 在 640×480 下即使将量化系数推至 `q=60~62`，复杂纹理画面仍存在约 `7.2~9.7 KB`（6~7 分片）的体积下限，但肉眼画质依然清晰锐利（见 `live-v25-vga15-final.json.phase1.png`）。
   - 手机单射频 2.4 GHz 热点需承载双向两跳空口（ESP32→手机 + 手机→电脑），且锁屏/省电模式会触发合包缓存：热点唤醒无干扰时三路 640×480 稳定在 **15~16.6 fps**；遇信道突发或热点合包时由 AIMD 自动护航保底不断流。如需全天候无波动稳定 15~20 fps，建议使用独立双频路由器（电脑接 5 GHz 或有线网口）。
