# 三路 PWM 舵机下位机

本工程用于当前多监测点项目：一块 STM32 管理三台 ESP32、三个二维云台、六个普通 PWM 舵机。
2026-11-06 用户已确认采用普通 PWM 舵机。

默认芯片为 **STM32F103C8T6，外部晶振 8 MHz，系统时钟 72 MHz**，Flash 按 64 KB、RAM 按 20 KB配置。
这是沿用参考板的开发配置；新板具体型号、晶振、舵机型号和机械行程仍需核对。

## 工程与构建

- Keil 工程：`MDK-ARM/displacement_tracker.uvprojx`
- 唯一构建目标：`displacement_tracker`
- 主入口及 HAL 接口：`Core/Src/main.c`
- 串口解析、跟踪和状态机：`Core/Src/tracker.c`
- 固件输出：`build/firmware/displacement_tracker.hex`

用 Keil 5 打开工程并构建；也可在本目录的 PowerShell 中运行：

```powershell
.\build.ps1
```

默认使用 `D:\Keil_v5\UV4\UV4.exe`，可以通过 `-UV4` 指定其他位置。脚本只编译。
工程使用 ARM Compiler 5，HAL/CMSIS 与启动文件已复制到项目内，没有对参考工程目录的编译依赖。
外设初始化由本项目手工维护，没有沿用旧 `.ioc`，不要用参考项目的 CubeMX 文件覆盖本工程。

## 接线

| 云台 | STM32 串口 TX / RX | PWM 水平 / 俯仰 |
| --- | --- | --- |
| 1 | USART1：PA9 / PA10 | TIM2 CH1 / CH2：PA0 / PA1 |
| 2 | USART2：PA2 / PA3 | TIM3 CH1 / CH2：PA6 / PA7 |
| 3 | USART3：PB10 / PB11 | TIM4 CH1 / CH2：PB6 / PB7 |

串口 115200-8-N-1：STM32 TX 接 ESP32 RX，STM32 RX 接 ESP32 TX，两边共地。
这些是普通舵机 PWM 信号，不连接参考无刷驱动板的三相输入。
舵机用独立、匹配型号的电源，电源地与 STM32/ESP32 地相连。

## 已实现的行为

- 三个串口分别拥有 RX 环形队列、帧解析器、跟踪状态和发送缓冲；中断只收字节和记录接收时间。
- 支持 `A5 5A / LEN / TYPE / PAYLOAD / CRC8`，大端 int16，CRC-8/ATM，多项式 0x07、初值 0。
- TYPE `01` 跟踪偏移、`02` 命令、`03` 心跳、`04` 手动设定两轴绝对角度；回传 `81` 遥测、`82` ACK。
- 手动上/下/左/右每次 1°；回中进入手动；`01` 命令明确进入手动，不是切换模式。
- 自动控制周期 20 ms，周期内只用最新偏移，每个新样本只消费一次；死区内不动，单次最大调整 2°。
- 普通上电保持无 PWM 脉冲。首次回中、手动步进、手动设角或超出死区的新自动偏移才开始输出。
- 自动启动清除旧偏移，等待启动后新数据。跟踪数据达到 200 ms 未更新就停止调整。
- 1 s 无合法控制帧则退出自动并保持原 PWM 指令，不主动回中；恢复心跳不会自动恢复跟踪。
- RX 溢出或串口错误会清空接收状态、退出自动；未知 TYPE 或错误载荷长度不刷新链路。
- 命令 ACK 遇发送忙时排队保留，队列满时不执行新命令。未知命令回 ACK，但不运动。
- 遥测周期 100 ms；`flags` bit0 为链路丢失，bit1 为当前指令角度达到限位。
- 独立看门狗约 1 s；异常处理先关闭六路 PWM。复位后重新等待明确运动操作。

普通 PWM 舵机没有位置反馈：遥测角度是**指令角度**，上电尚未输出 PWM 时也是预设值，不能据此断言实际朝向。
停止和失联时保持 PWM 并不等于切断舵机供电。

## 参数与方向

默认 `Tracker_DefaultConfig()`：180° 舵机、500～2500 µs 脉宽、90°中心、15°～165°软件行程、死区 8 像素、Kp=0.00625。
50 Hz PWM 使用 1 MHz 计数，ARR=19999，PSC=71。

这些是开发默认值，不代表已经测得新舵机规格。参考旧 `servo_duoji.c` 实际按 **270°** 映射，不能直接复制其角度参数。
若使用 270° 舵机，应同时设置 `span_deg`、中心和限位；脉宽范围按型号及实测确定，配置限制在 500～2500 µs 内。
在 `main.c` 初始化每路 `TrackerConfig` 时可以分别设置六个轴，配置非法则不启动控制。

每轴 `direction` 只能是 +1/-1，默认 -1。手动与自动共用方向映射：手动右/下和正 x/y 偏移的调整同向。
首次接线后以用户观察到的手动实际方向校准符号，再验证自动闭环；代码测试不能证明物理方向。

## 参考来源及协议差异

参考目录：`D:\STM32CubeMx\hal_stm32\科教协同下位机-1`。

- 参考 Keil 当前入口是 `main_gimbal.c`，用于无刷电机 + AS5600；其 FOC、编码器、Flash 校准、OLED和接线没有移入本工程。
- 参考旧 `main.c` / `servo_duoji.c` 的 PWM 定时方式、舵机角度换算和协议思路，针对三路普通舵机重写应用逻辑。
- 复用了本地 HAL/CMSIS、`system_stm32f1xx.c`、启动文件，并裁剪 HAL 模块配置；原文件版权声明保留。
- `reference_sources.json` 记录复制文件来源、源 SHA256 和是否修改。原项目保持原样。

旧固件 TYPE `04` 是“方向 + 步长”，本项目 TYPE `04` 是“两轴绝对角度”；旧命令 `01` 是切换模式，
本项目为进入手动。旧 HEX 不能直接配本协议。UART ACK 只有命令码，ESP32 后续应保证每路一次只有一个待确认命令，
并按 UDP request 去重；STM32 不具备 UDP request 信息，不能替代 ESP32 的去重。
