# ESP32 推流优化记录（2026-11-06）

最新状态见文末“后续：目标固定无线320×240 @20fps”。下方早期阶段采用RGB565/250ms超时，
不代表当前源码；当前已改YUV优化编码、1000ms发送等待，并提高验收标准。

目标：在用户当前可用的 DH4504 网络中改善320×240连续显示。电脑后续已切换到同一2.4GHz SSID/信道8。
已有整片Flash备份及芯片端校验，授权范围包括代码优化和实板刷写。

## 当前正式改动

- 软件 JPEG 质量80改40，典型同场景帧大小由约4.2KB降至约2KB，牺牲部分画质以减少带宽。
- HTTP multipart JPEG帧仍合并为一个缓冲，关闭 `TCP_NODELAY`，允许TCP合并分块长度行等小段。
- 增加250ms socket发送等待，发送失败断开；上位机已有看门狗与重连。这个等待不是整个连接/整帧延迟的硬上限。
- Qt增加新图像实际绘制统计和实机验收程序；补充本机运行依赖部署脚本与 `host/run.cmd`。
- 增加 `tools/check_esp32_stream.py`：统计完整请求时段的逐秒帧数、首帧、最长无帧、解码错误、重连和串口重启。
  最大无帧包含开始与结尾的空白段，避免只计算已收到图像间隔而漏掉最后的长冻结。

固件保留标准MJPEG、RGB565 +原编码路径及原引脚。新编码器等实验没有在没有显示验收的情况下替换默认实现。
没有操作STM32、舵机或用户其他项目。

## 后续：目标固定无线320×240 @20fps

用户明确要求无线320×240 @20fps；160×120和USB预览均不替代这个目标。
环境仍为DH4504、板载天线、USB供电、距路由器约6米；用户当前不能移动设备或换网络。

### 已保留的源码改动

- Arduino-ESP32 2.0.17隔离工具链，保持原3.3.12安装不变。
- 复用本机官方S3 `esp_new_jpeg` 库的优化软件编码器，GC2145输入从RGB565改YUV422。
- 双缓冲/最新帧覆盖，采集间隔40ms，编码句柄及对齐工作缓冲复用；JPEG质量40。
- 标准HTTP MJPEG；每帧携带 `X-Frame-Seq` 便于测量，发送等待1000ms仍不是整帧硬上限。
- `esp32cam/build.ps1` 固定构建和烧录依赖，构建目录使用ASCII路径，清单记录源码、编码库与应用SHA256。
- Qt验收默认提高至320×240、逐秒至少20帧、最大无帧150ms，保存实际阈值和分辨率。

本轮板端独立实测连续约25.0～25.2fps，编码约16.7～17.2ms/帧；旧路径约67ms/帧。
板端瓶颈已明显改善，但不构成无线显示20fps的证明。
