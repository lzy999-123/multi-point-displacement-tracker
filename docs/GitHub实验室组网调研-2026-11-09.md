# GitHub ESP32-CAM 实验室组网调研

目标：三台 ESP32-CAM 通过实验室局域网向 Qt 分别推送视频，Luckfox 也接入该局域网。相机独立热点不是最终方案。

通过 GitHub 官方 API 读取仓库元数据、固定提交的README和关键源码；未执行第三方仓库脚本，未烧录第三方预编译固件。
下面的作者能力说明不等于本机已验证的帧率或延迟。原始资料保存在 `tmp/lab-wifi-20261109/github/`。

## 采用方法

保留当前VID1与Qt三通道结构，先用无视频负载的UDP/TCP应答验证网络，再逐步启用摄像头与推流。
关闭WiFi休眠、有限缓冲和重试当前已存在；不以项目星标数或作者帧率代替本机验收。
固定STA模式；比较PC在实验室2.4GHz和5GHz下的路由，读取实际IP、串口请求与发送结果。

新增 `esp32cam/network_probe/network_probe.ino` 是本项目自己的临时诊断程序，可在摄像头关闭/开启时测试：
普通UDP回复、局域网广播回复、TCP HTTP回复、不同发射功率以及b/g与b/g/n模式。
它不是正式固件，诊断结束必须恢复并验证正式相机固件。

另在GitHub发现同类ESP32-CAM的[新版核心OTA连接问题 #12790](https://github.com/espressif/arduino-esp32/issues/12790)，
只是SDK版本对照的线索，其症状与本机不完全相同，不认定为本项目根因。
隔离工具链对照只使用乐鑫发布的源码和编译器，编译器下载后核对官方包索引SHA256；不替换已有3.3.12安装。
