> 2026-11-16：正式双档为ID0=VGA12、ID1=QVGA25；上位机记住上次选择，不再固定启动10fps。ID2（baseline10）继续作为显式诊断兼容档位。v18的ACK等待从整帧最后一次提交完成后计时，避免发送重试时间先耗尽确认期限。配置确认不等于无线帧率达标。

v19保持协议目标值12/25不变；VGA源发送周期为76ms（约13.16fps），为每秒至少12张实际新绘制留调度余量，QVGA周期40ms。不是把验收下限改为11fps。

# 通信协议：上位机 ↔ ESP32-CAM ↔ STM32

状态：协议 v1。2026-11-06 已在 `stm32/` 实现本文的三路串口协议并完成构建和软件测试；UDP 控制会话与 ESP32 串口转发仍待实现，实物联调未验收。串口帧格式参考 untitled7 的 UART 协议 v2，按普通 PWM 舵机云台做了调整。

## 1. 设备发现（UDP 39093）

上位机向 `255.255.255.255:39093` 广播请求，每台 ESP32-CAM 单播回复。

请求：

```json
{"type": "discover", "version": 1, "nonce": "随机字符串"}
```

回复：

```json
{"type": "announce", "version": 1, "nonce": "原样返回", "id": 1,
 "ip": "192.168.1.101", "stream": "http://192.168.1.101:81/stream", "udp_stream": 5006, "control_port": 5005}
```

`id` 为 1～3，写在 ESP32-CAM 固件配置里，对应 STM32 的串口号和云台编号。上位机按 `id` 把设备分配到通道，
不按 IP 分配（IP 可能因 DHCP 变化）。两台设备报告相同 `id` 时，上位机提示冲突并不连接后来的那台。

## 2. 视频（HTTP 81）

`GET /stream` 返回 `multipart/x-mixed-replace; boundary=frame`，每部分是一张 JPEG，带 `Content-Length` 头。
同一时刻只服务一个客户端。当前普通 ESP32-CAM＋OV3660 使用硬件 JPEG、VGA 640×480；此前 GC2145 软件 JPEG 的 QVGA 320×240 记录属于历史配置。

### 2.1 VID1 UDP 视频（5006，当前优先使用）

上位机每500ms向相机 UDP 5006发送ASCII `VREQA`，相机向请求的源IP和源端口发送图像。
每台相机只保存一个活动接收端；最后收到的有效请求会更新目的地址，10秒无心跳则停止UDP推流。
上位机自动发现收到合法 `udp_stream` 端口后优先使用该协议。

`VREQA` 的最后一个字节协商接收反馈；旧固件仍识别前四字节 `VREQ`。新固件收到旧客户端的
四字节 `VREQ` 时继续使用无反馈模式。反馈模式下，上位机在合法分片收齐时立即向同一对端发送
六字节 `VACK` 加小端 uint16 帧序号；每张收齐图像独立确认，包括被更新图像替代而未解码的帧。
ACK 仅表示分片组装完整，不表示 JPEG 有效或已经显示；残缺帧和不合法报文不确认。相机同时最多允许两张已完整提交的图像
等待确认，窗口初始为一帧；连续30次有效ACK后升为两帧，发送缓冲不足时立即回到一帧。
仅保存各自的序号与时刻，不缓存旧JPEG用于重传。ACK序号及来源必须匹配当前接收端，允许确认乱序到达。每张150ms（从本帧开始提交计时）仍未确认时释放对应槽位，
下一次读取最新采集图像，不重发历史整帧。此反馈控制本地积压，不保证无线交付或光学延迟。

每个报文为16字节头加JPEG分片；多字节字段为小端：

| 字段 | 字节数 | 内容 |
| --- | --- | --- |
| magic | 4 | ASCII `VID1` |
| device_id / reserved | 1 / 1 | 编号1～3 / 0 |
| frame_seq | 2 | 帧序号，65535后回绕 |
| chunk_index / chunk_count | 1 / 1 | 从0开始的片号 / 总片数 |
| payload_size | 2 | 本片JPEG字节数 |
| frame_size | 4 | 完整JPEG字节数，当前最多65536 |

每片最多1400字节，除末片外长度必须为1400；总片数必须等于 `ceil(frame_size/1400)`。
同帧各分片元数据必须一致。Qt只接收配置对端的报文，校验长度后以8个有限槽位重组，
按完整序号查找槽位，避免采集序号跳跃时取模冲突。收包、组帧、ACK 和心跳运行在专用线程，
socket 请求 1MiB 接收缓冲；组帧缓冲预留并复用。通过带锁的单帧缓冲向检测线程交付最新 JPEG，
检测线程执行解码、检测和显示转换，处理期间收包继续运行。重复、倒序和过期图像不会重复显示。
1.5秒没有成功解码时清除序号基准，允许相机重启后的序号归零恢复。
VID1不携带曝光时刻或跨重启会话标识，因此接收/显示帧间隔不能解释为光学端到端延迟。

### 2.2 双档 UDP 配置（VREQA3，2026-11-15）

VREQA3 是固定 16 字节的心跳/配置请求，仍发往 UDP 5006，每 500ms 重发。
各字段：0..5 为 ASCII `VREQA3`；6 为目标 fps；7/8 为质量范围；9 为 TOS；
10..11 为目标 JPEG 长度（小端）；12 为档位（0=640×480/12fps，1=320×240/25fps）；
13..14 为随机配置代次（小端 uint16）；15 保留为 0。
固件以档位定义的分辨率、fps 和压缩范围为准，避免非法组合；旧 VREQ/VREQA/VREQA2 仍能接入。

采集任务独占传感器配置，切换后丢弃 3 张过渡帧；校验 JPEG SOF 为请求尺寸后发布，并允许 UDP 发送。
相机定期回复 16 字节 VCFG：0..3 为 `VCFG`；4 为设备编号；5 为档位；6..7 为代次；
8..9 为宽；10..11 为高；12 为目标 fps；13 为状态（0=应用成功）；14..15 保留。
上位机核对对端、编号范围、代次、档位及实际尺寸，确认仅代表配置已应用，不代表稳定帧率。
VID1 头的 reserved 在 V3 会话下为档位+1；接收端还校验解码后的宽高，过滤切换前残留图像。

V3 反馈窗口在 VGA 为 3～4 张、QVGA 为 6～8 张，等待上限 300ms（从整帧提交完成后计时）；匹配的较新 VACK
同时释放旧帧信用额度，旧帧不阻塞新完整画面。缓存只用于新鲜残帧补片，超期仍丢弃。
VNCK 为 14 字节：`VNCK` + 小端 uint16 序号 + 小端 uint64 缺片位图。
仅对 250ms 内、最多缺 3 片的帧申请，最多两次；相机只对当前接收端及 300ms 内缓存回应。
VSTP 为 4 字节，当前接收端主动关闭时立即释放推流会话，减少旧会话残留。
所有视频与反馈报文均走 UDP，无自动 HTTP 回退。

## 3. 控制（UDP 5005，JSON）

每条消息都包含 `version: 1`、`session`（上位机随机生成）和 `type`。ESP32 只接受当前会话所属的源 IP 和端口。

| 方向 | type | 字段 | 说明 |
| --- | --- | --- | --- |
| 上位机 → ESP32 | `hello` | | 建立会话，ESP32 回 `welcome` |
| ESP32 → 上位机 | `welcome` | `id` | 会话建立；不代表 STM32 在线 |
| 上位机 → ESP32 | `heartbeat` | | 每 100ms 一次；ESP32 1s 未收到则释放会话 |
| 上位机 → ESP32 | `track` | `seq`，`x`，`y`（int16） | 目标中心减画面中心的像素偏移，右为 x>0，下为 y>0 |
| 上位机 → ESP32 | `command` | `request`，`cmd` | 命令码见 4.3；request 在会话内递增 |
| 上位机 → ESP32 | `set_angle` | `request`，`pan`，`tilt`（0.1° 单位整数） | 手动直接设定角度，用于调试和标定 |
| ESP32 → 上位机 | `status` | `seq`，`online`，`mode`，`pan`，`tilt`，`flags` | STM32 遥测转发，角度单位度；`online` 表示 STM32 遥测未超时 |
| ESP32 → 上位机 | `ack` / `command_failed` | `request`，`cmd` | ack 只能来自 STM32 的串口 ACK |
| 上位机 → ESP32 | `bye` | | 释放会话，ESP32 向 STM32 发停止跟踪 |

规则：

- `track` 按 `seq` 丢弃乱序和重复数据；ESP32 每个新 `seq` 只向串口转发一次，两次转发至少间隔 20ms，间隔内只转发最新值。
- 上位机命令 200ms 未收到 ack 就用同一 `request` 重发，最多 3 次。ESP32 按 `request` 去重，不会重复执行。
- ESP32 等串口 ACK 超过 300ms 时回 `command_failed`，会话保留。
- UART ACK 只有命令码，ESP32 每路同时只能保留一个待确认串口命令，UDP 重发按 `request` 去重；旧命令的迟到 ACK 不得确认为后续请求。
- 本版不做消息签名，只在实验室局域网使用。

## 4. 串口帧（ESP32 ↔ STM32）

物理层：UART 115200-8-N-1，3.3V。多字节字段为大端（高字节在前）。

### 4.1 帧结构

```
+------+------+-----+------+-------------+------+
| 0xA5 | 0x5A | LEN | TYPE | PAYLOAD ... | CRC8 |
+------+------+-----+------+-------------+------+
```

- `LEN` = PAYLOAD 长度 + 1（包含 TYPE），范围 1～32。
- `CRC8`：对 LEN、TYPE、PAYLOAD 计算，多项式 0x07，初值 0x00（CRC-8/ATM）。
- 解析器失步或 CRC 错误时丢弃 1 字节，继续寻找 `A5 5A`。

云台编号由 STM32 的串口号决定（USART1 = 云台 1，依此类推），帧内不带编号。

### 4.2 帧类型

ESP32 → STM32：

| TYPE | 名称 | PAYLOAD | 说明 |
| --- | --- | --- | --- |
| 0x01 | TRACK_DATA | int16 x，int16 y | 像素偏移，仅自动模式使用 |
| 0x02 | CMD | uint8 cmd | 必须回 ACK，未知命令码也回 ACK 但不执行 |
| 0x03 | HEARTBEAT | 无 | 会话有效期间每 200ms 一帧 |
| 0x04 | SET_ANGLE | int16 pan×10，int16 tilt×10 | 仅手动模式执行，超出限位时裁剪；回 ACK（cmd 字段填 0x04） |

STM32 → ESP32：

| TYPE | 名称 | PAYLOAD | 说明 |
| --- | --- | --- | --- |
| 0x81 | TELEMETRY | uint8 mode，int16 pan×10，int16 tilt×10，uint8 flags | 每 100ms 一帧；mode 0=手动，1=自动；角度为**指令角度** |
| 0x82 | ACK | uint8 cmd | 对 CMD 或 SET_ANGLE 的应答 |

flags：bit0 链路丢失（1s 未收到合法帧），bit1 角度到达限位，其余为 0。

### 4.3 CMD 命令码

| cmd | 含义 |
| --- | --- |
| 0x01 | 进入手动模式（停止跟踪，保持当前角度） |
| 0x02 | 回中（到配置的中位角度），并进入手动模式 |
| 0x11 | 进入自动模式，开始跟踪 |
| 0x12 | 停止跟踪（进入手动模式，保持当前角度） |
| 0x20～0x23 | 手动上 / 下 / 左 / 右步进 1°（仅手动模式） |

### 4.4 超时

| 机制 | 参数 | 行为 |
| --- | --- | --- |
| 跟踪数据超时（STM32） | 200ms 无 TRACK_DATA | 不再调整角度，保持当前位置 |
| 链路超时（STM32） | 1s 无任何合法帧 | 停止跟踪并保持角度，flags bit0 置位 |
| 会话超时（ESP32） | 1s 无心跳 | 释放会话，向 STM32 发 CMD 0x12 并停止串口心跳 |
| 遥测超时（ESP32） | 1s 无 TELEMETRY | `status.online = false` |
| 状态超时（上位机） | 1s 无 status | 该通道显示离线，禁用控制 |

普通上电时 STM32 不输出 PWM；首次手动运动、回中、设角或启动后收到超出死区的新跟踪偏移才启用。
重新进入自动模式会清除旧偏移；失联退出自动后，恢复心跳或偏移帧不会自行恢复自动，必须重新发送启动命令。
RX 溢出或串口错误同样退出自动并清理接收状态，保持已有 PWM 指令。

## 5. 跟踪控制（STM32）

控制周期 20ms（50Hz，与舵机 PWM 周期一致）。自动模式下，收到新的偏移后：

```
pan  -= Kp_pan  × x    （方向符号按实际安装调整）
tilt -= Kp_tilt × y
```

再裁剪到软限位。`|x|`、`|y|` 小于死区（如 8 像素）时不调整，避免在中心附近抖动。
Kp 初值按"偏移 320 像素时每次调整约 2°"估算，实测后调整，必要时加积分项或限制单步最大调整量。

当前实现每 20ms 最多消费一个最新偏移，每个样本只使用一次，默认死区包含边界 `|x| <= 8`、`|y| <= 8`，单步限幅 2°。
参考旧下位机的 TYPE `0x04`（方向 + 步长）与本项目 TYPE `0x04`（两轴绝对角度）不同，命令 `0x01` 的含义也不同，不可直接混用旧 HEX。
