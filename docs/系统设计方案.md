# 基于视觉的多监测点位移跟踪系统：设计方案

状态：分阶段实现中。三路视频检测已有代码；2026-11-06 新增三路普通 PWM 舵机 STM32 固件，完成构建与软件测试，控制链路和实物闭环仍待联调。标注"待确认"的项需要核对实物后再定。

## 1. 目标

3 个监测点各由一个二维舵机云台和一台 ESP32-CAM 负责。上位机接收 3 路视频，识别目标（当前为色块），
算出目标偏离画面中心的像素量，经 WiFi 发给对应 ESP32-CAM，再由串口转给 STM32，STM32 驱动舵机让目标保持在画面中心。
上位机同时根据云台角度和像素偏移计算各监测点的位移，实时显示曲线并导出数据。

后期扩展：一路画面中多个目标、人脸跟踪。

## 2. 系统架构

```
                 WiFi（同一热点/路由器）
上位机 Qt ───────┬──── ESP32-CAM #1 ──UART──┐
  · 3 路视频显示 ├──── ESP32-CAM #2 ──UART──┼── STM32 ──PWM── 云台1/2/3（各 2 个舵机）
  · 目标检测     └──── ESP32-CAM #3 ──UART──┘
  · 位移计算
```

每个 ESP32-CAM 对上位机提供两个通道：

| 通道 | 方式 | 内容 |
| --- | --- | --- |
| 视频 | HTTP MJPEG，端口 81，`/stream` | JPEG 帧流 |
| 控制 | UDP，端口 5005 | 目标偏移、命令、心跳（上行）；状态、ACK（下行） |
| 发现 | UDP 广播，端口 39093 | 上位机查找 3 台设备的 IP 和编号 |

STM32 用 3 个独立串口分别连接 3 台 ESP32-CAM，**由串口号区分云台**，所以串口帧不需要云台编号。

| 二维舵机云台支架 | 3 | |
| 舵机电源 | 1 | 5～6V，电流按舵机堵转电流 ×6 选，**不能从 STM32 板取电** |
| ESP32-CAM 电源 | 3 | 5V，每台 ≥500mA，开 WiFi 时电流尖峰大，电源不稳会反复重启 |

所有电源的 GND 必须共地。

### 3.2 STM32F103C8T6 引脚规划（待确认型号后调整）

F103C8T6 正好有 3 个 USART 和足够的 PWM 通道：

| 功能 | 外设 | 引脚 |
| --- | --- | --- |
| 云台 1 串口（接 ESP32-CAM #1） | USART1 | PA9 TX，PA10 RX |
| 云台 2 串口 | USART2 | PA2 TX，PA3 RX |
| 云台 3 串口 | USART3 | PB10 TX，PB11 RX |
| 云台 1 水平 / 俯仰舵机 | TIM2 CH1 / CH2 | PA0 / PA1 |
| 云台 2 水平 / 俯仰舵机 | TIM3 CH1 / CH2 | PA6 / PA7 |
| 云台 3 水平 / 俯仰舵机 | TIM4 CH1 / CH2 | PB6 / PB7 |

舵机 PWM：50Hz（周期 20ms），定时器计数 1MHz，脉宽 500～2500µs 对应 0°～180°，
1 个计数约 0.09°。实际脉宽范围按舵机型号标定，并设软限位防止撞到支架。

STM32 TX 接 ESP32 RX，STM32 RX 接 ESP32 TX，两边都是 3.3V 电平，可直接相连。

### 3.3 ESP32-CAM 串口

当前开发板是 ESP32-S3。UART0（GPIO43/44，接板载 CH340）用于烧录和日志，与 STM32 通信另用 UART1，引脚可任意映射。
不能用的引脚：GPIO4～13、15～18（摄像头）、GPIO35～37（PSRAM）、GPIO19/20（USB）、GPIO0/3/45/46（启动配置）。
候选是 **GPIO41（TX）/ GPIO42（RX）** 或 GPIO1/GPIO2，阶段 2 接线前按板子丝印确认引出了哪些引脚。

### 4.3 ESP32-CAM 固件

- 摄像头初始化，HTTP 服务器在 81 端口输出 MJPEG。GC2145 没有硬件 JPEG，取 RGB565 后由 CPU 压缩：实测 QVGA 约 64ms/帧、VGA 约 263ms/帧，所以默认 QVGA（320×240）。压缩在核 1，网络发送在核 0。
- UDP 控制服务：会话、心跳、命令去重、把命令转成串口帧发给 STM32、把 STM32 的状态和 ACK 回传。逻辑参考 untitled7 的 `board/luckfox/luckfox-control.py`。
- 发现服务：响应广播，回复设备编号、IP 和视频地址。
- 设备编号和 WiFi 账号写在配置头文件里，不提交到仓库。

### 4.4 STM32 固件

- 3 个串口用中断/DMA 接收，各自有独立的帧解析器和链路超时。
- 每个云台保存目标角度，50Hz 控制循环：自动模式下按像素偏移做比例（或 PI）调整角度，限位后写入 PWM。
- 舵机没有角度反馈，回传的是**指令角度**，不是实测角度。
- 链路超时（1s 无心跳）或收到停止命令时停止跟踪，保持当前角度。

当前工程见 [STM32 说明](../stm32/README.md)：参考 `D:\STM32CubeMx\hal_stm32\科教协同下位机-1` 中旧 PWM 舵机代码及协议思路，独立实现三路串口、六路 PWM。
该参考工程当前编译入口实际是无刷版本 `main_gimbal.c`；其 FOC、AS5600、Flash 校准及引脚分配不适用于本项目。
新固件默认上电不输出 PWM，参考板的 8MHz 晶振和 F103C8 型号也应在接新硬件前确认。

## 5. 位移计算

符号：`θ` 为云台指令角度，`Δu` 为目标相对画面中心的像素偏移，`f` 为相机焦距（像素），`D` 为相机到监测点的距离。

1. 目标方向角：`α = θ + atan(Δu / f)`，水平、垂直各算一次。
2. 位移：`s = D · (tan(α) − tan(α₀))`，`α₀` 为开始测量时的基准方向。
3. `f` 通过棋盘格标定得到，`D` 现场用卷尺测量。

精度限制：

- 舵机有死区和回差，指令角度与实际角度存在误差。小位移时以像素偏移为主，测量时可以先让云台停住，只用像素量计算。
- ESP32-CAM 画质和帧率有限，色块边缘噪声会造成质心抖动，需要滤波。
- 视频帧和角度状态不是同时采样的，云台运动过程中的数据误差较大。
