# OV3660 实机编译与图像优化（2026-11-09）

## 当前结果

COM5 实测：ESP32-D0WD-V3 rev3.1，4MB Flash、4MB PSRAM，OV3660 PID `0x3660`。
320×240 硬件 JPEG、20MHz XCLK。已收到真实图像并用实际 Qt 检测、绘制路径统计。

本轮单客户端直连 HTTP 的 30 秒窗口：显示 724 张新图像，约 24.1fps；首帧 456ms，
预热后最少一秒 7 张、最大无新画面间隔 740ms，没有重连。
严格要求为每秒至少20帧且最大间隔150ms，本轮未通过该标准。
不能用平均帧率或窗口瞬时的29fps替代流畅性验收。

## 实施调整

- `esp32cam/build.ps1` 默认普通 ESP32-CAM，Arduino-ESP32 3.3.12，DIO/40MHz；
  `-Board S3` 保留旧板 2.0.17 路径。两板 Flash 和 bootloader 偏移独立。
- OV3660 直接硬件 JPEG；S3 GC2145 专用寄存器与软件编码库不作用于普通 ESP32。
- WiFi 带宽在关联前设置，关联后设置发射功率；增加断线周期重连。
  低功率对照并未单独解决问题，不宣称功率是根因。
- 提供 WPA2 私有直连热点 `disp-cam-1`，地址 `192.168.4.1`，保留路由器上联和 NAPT。
  直连单张 `/capture` 对照约140～245ms。NAPT不保证互联网可用性。
- 使用 SDK 默认 WiFi 缓存数量；未将该调整单独归因为性能收益。
- Qt HTTP 绕过系统代理；自动发现优先 HTTP，UDP 保留手动诊断。
- 测试期间关闭另一个从 Qt Creator 目录启动的旧上位机，它持续请求 UDP、造成资源竞争。
  已将更新的 EXE 同步到本机 Qt Creator Release 路径。
- `host/run-direct.cmd` 连接摄像头、启动正式窗口，关闭窗口后恢复原 WiFi。
  密码仅从忽略版本控制的本地 `secrets.h` 读取，不写进日志或文档。
