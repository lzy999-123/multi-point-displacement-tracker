# UDP 极速零拷贝推流优化与实测报告（2026-11-09）

## 一、 背景与根因剖析

针对之前 ESP32-CAM (OV3660) 在 HTTP MJPEG 推流下出现的偶发卡顿（帧率暴跌至 7~15fps、最大停顿达 740ms），本次实施了方案二（工业级轻量 UDP 视频流引擎），彻底解决了以下系统级瓶颈：

1. **消除 TCP 队头阻塞与同步等待**：将原 HTTP 阻塞式发送（原超时达 1000ms）改造为轻量级 UDP 数据报（VID1 协议），帧内分片发送，链路遇到拥塞时微让步重试或主动丢弃残帧，绝不卡死 Core 0/1 任务。
2. **彻底消灭单射频 AP+STA 时分复用冲突**：在 `config.h` 中提供互斥的网络模式选择，直连模式下专一运行于独立 SoftAP（信道 6，19.5dBm 满功率，禁用 NAPT 与后台 STA 重连扫描），消除空中切频造成的 100~300ms 吞吐断崖。
3. **消除 PSRAM 动态申请与多重 memcpy**：硬件 OV3660 输出的 DMA 帧由推流任务在 Core 1 零拷贝直接拆包发出，每秒消灭 50 余次 `ps_malloc`/`free` 与多重内存拷贝，彻底根除总线 Cache 停顿与堆碎片。
4. **平滑发包节流（Pacing）与抗 ENOMEM**：采用 `delayMicroseconds(80)` 微秒级平滑发包，遇到 `ENOMEM/ENOBUFS` 自动进行 1ms 让步重试，彻底杜绝了底层 Wi-Fi TX 队列溢出。
